# Maxima Fiction Book Editor 0.0.5 - release notes

Draft of the GitHub release text for tag `v0.0.5` (date to be filled when the tag is made). The
release workflow (`.github/workflows/release.yml`, step "Checksums and release notes") writes
the headline, the table of packages per platform, the SmartScreen note, the link to

is in `CHANGELOG.md`.

## An AI assistant that changes the book on request - and stays out of the way until asked

Release 0.0.5 adds the AI assistant the requester asked for: you tell it in plain words what to
change in the open book - in the Body view or in the Source view - and it makes the change,
which must be a valid FictionBook 2.1 change before it reaches the document. It talks to AI
services that speak the request format introduced by OpenAI: two free services that need no
account and no key are bundled, OVHcloud AI Endpoints first, and a service of your own - a paid
one with a key, or a model server on your own computer - works as well. The assistant is an
optional mode, not a permanent presence: the editor starts without it, View > AI Assistant turns
it on, closing the panel turns it off, and *Disabled* in Settings removes it from the editor
altogether. The editor still works fully offline; the assistant's requests are the second of
exactly two things that ever use the network (the first is the check for a new version), and
both happen only on your action. No bundled script changes its behaviour.

## What is new

1. **Settings > AI assistant.** A new settings page with three choices. *Free service (no
   registration)* - the default - lists the bundled services as "name - model": OVHcloud AI
   Endpoints (`gpt-oss-120b`) and Pollinations (`openai-fast`), each with its limits note in
   the interface language and a link to its terms. *Test connection* sends one small request and
   reports "answered (model)" or the failure in the service's own words. The list comes from a
   file: the bundled `ai-services.json` is always read, and a copy of your own - *Edit list*
   creates it in your data folder and opens the folder - adds services, corrects a stale address
   or hides an entry; *Reload list* applies it. *My own service and key* and *Disabled* are
   items 8 and 9 below.
2. **The first request to a hosted service asks first.** Before anything leaves the computer for
   a service - the first request, *Test connection* or *Fetch models* alike - a notice names the
   service, says that your instruction and the parts of the book the assistant reads will be
   sent to it, links to its terms and offers Yes / No. Yes is remembered for that service (the
   page lists the agreements with *Withdraw*); No sends nothing. A server on your own computer
   is never asked about. A plain `http` address that is not on this computer is accepted with a
   warning that the text travels unencrypted.
3. **The panel.** View > AI Assistant (Ctrl+Shift+A; Cmd+Shift+A on macOS) or the new toolbar
   button turns the assistant on and opens a panel on the right - a divider sets its width,
   which is remembered - with the service and model in use, the conversation, an activity list
   that names what the assistant did (read the outline, read section 3, replaced a title,
   validated ...), the elapsed time and the phase while a request runs, and the instruction
   field: Enter sends, Shift+Enter inserts a newline, Send becomes Stop while the service
   works. While a request runs the document is locked exactly as during a script run, with the
   banner naming the service and model and offering Cancel. Everything one request changed is
   one undo step: the panel's *Undo* button and Edit > Undo take it back. A question is answered
   in the panel without a change; when the assistant is unsure it asks back. Closing the panel
   turns the assistant off and drops the conversation; nothing of it is written to disk.
4. **Ask AI... on the selection.** With the assistant on, the context menu of the Body view and
   of the Source view gains *Ask AI...* (Ctrl+K): a small popup opens next to the selection,
   shows how much is selected and which service will answer, takes one instruction and replaces
   the selection with the result - emphasis and footnote links kept where the service kept them,
   the replacement selected, *Done* with *Undo*. Without a selection the paragraph at the caret
   is the context and the instruction is handled as in the panel. A question gets its answer in
   the popup with *Continue in panel*. Escape cancels a running request and leaves the document
   as it was. In the Source view the selected XML goes to the service as XML and the returned
   XML must leave the document well-formed and valid before it is applied.
5. **The catalogue of operations.** The editor offers the service's model its operations as an
   MCP catalogue (the open standard by which AI programs discover another program's tools) -
   22 tools: the working context, the outline, parts of the book, the selection, the
   description, search, validation and the FB2 schema for reading; the selection, a node, a
   text, every occurrence of a text and the description for changing; the scripts for listing,
   reading, running and proposing. The catalogue serves the editor's own assistant only -
   nothing listens for other programs - and runs inside the editor's own page. Text the model
   needs is sent whole where it fits and in parts along paragraph or section boundaries where it
   does not; images never travel.
6. **Nothing invalid reaches the book.** Every change the assistant proposes - a replaced
   paragraph, a new section, a changed description, a spliced piece of XML - is applied to a
   working copy and checked against the FB2 2.1 schema first. A change that adds a schema error
   the document did not have is refused, the errors go back to the model with the element and
   the position, and the model corrects itself; the third refusal of the same change ends the
   request with nothing of it applied and the errors shown to you. The model can ask for the
   whole schema or for one element's content model.
7. **Scripts through the assistant.** "Run the script that removes spaces before punctuation on
   the whole book" finds the script in the catalogue and runs it exactly as the Scripts menu
   would - its own dialogs included, captioned with the script's name and "run by the AI
   assistant" - inside the request's single undo step; Cancel on the banner cancels script and
   request together. "Make me a script that ..." has the assistant read the scripting interface
   and propose a complete script package: a dialog shows every file in full and the target
   folder, and *Write*, *Write and run* or *Don't write* is your decision - nothing is written
   before it. A written script lands in your user scripts folder under the group
   `90_assistant`, is in the Scripts menu at once and has the rights and limits of every user
   script; a bundled script is never modified - a change to one is proposed as a new user
   script.
8. **My own service and key.** Enter the address of a service, its key and a model - *Fetch
   models* offers the list the service returns, and a typed name is accepted when it lists none
   -, press *Test connection* and OK. Red text says the connection is not tested; a successful
   test turns it green with the model's name, and an edit of the address, the key or the model
   turns it red again until the next test; the same values are green again when the page is
   reopened. A model server on your own computer (llama.cpp, Ollama, LM Studio and the like,
   `http://127.0.0.1:11434/v1` say) is such a service with an empty key: no notice, no network
   beyond your computer. The key is stored with the settings - so a portable copy takes it along
   -, shown masked and never written to the diagnostics log; a refused key is reported in the
   service's own words with a link to the settings page.
9. **Disabled.** Choose *Disabled* in Settings > AI assistant and press OK: the View entry, the
   toolbar button, the hotkeys, the context-menu entry, the panel, the popup and the notice are
   gone, no request leaves the editor and no code of the feature runs - without a restart, and
   still after one. The settings page is the only place where the assistant exists then, so that
   it can be enabled again; choosing *Free service* or *My own service and key* brings the entry
   back, with the assistant off until you turn it on.
10. **Limits handled, slow services shown.** The free services are rate-limited (the notes on the
    settings page say how). When one answers "wait" - a 429, a 402 or an overloaded 503 that
    names the wait - the assistant waits the named time with a visible, cancellable countdown
    and tries again, up to 5 minutes per request; a quota that would take longer (a daily
    quota, for instance) ends the request with the advice to try later or choose another
    service. Every answer arrives whole, with its elapsed time shown; OVHcloud's `gpt-oss-120b`
    took about 25 seconds for a short proof-read when the services were verified (2026-10-22).

## Upgrading from 0.0.4

- **Settings.** The settings file keeps every value. New keys take their defaults when they are
  absent: `ai.mode` (`free`), `ai.freeServiceId` (`ovhcloud`), `ai.custom.address`,
  `ai.custom.key` and `ai.custom.model` (empty), `ai.customVerified` (the empty record),
  `ai.agreements` (none) and `session.aiPanelWidth` (`360`). Nothing contacts a service until
  you turn the assistant on and send an instruction, or press *Test connection* or *Fetch
  models* on the page; the editor itself never does.
- **Network.** 0.0.4 made exactly one kind of network request, the check for a new version. 0.0.5
  makes exactly two: that check, unchanged, and the assistant's requests to the service you
  chose, only on your action, only after your agreement for a hosted service, never while the
  assistant is off and never under *Disabled*. The requests are made by the editor's core, which
  takes its proxy from the environment variables (`https_proxy`, `http_proxy`, `all_proxy`,
  `no_proxy` and their upper-case forms); addresses on this computer are always reached
  directly. Certificates are verified by the system store on Windows and macOS and, on Linux, by
  the first of `SSL_CERT_FILE`, `CURL_CA_BUNDLE`, the distribution's bundle
  (`/etc/ssl/certs/ca-certificates.crt`, `/etc/pki/tls/certs/ca-bundle.crt`,
  `/etc/ssl/ca-bundle.pem`, `/etc/ssl/cert.pem`) and the Mozilla CA bundle the Linux packages
  ship (`share/mfbe/resources/certs/cacert.pem`, with its notice - Help > About shows it on
  Linux). Verification is never relaxed, TLS 1.2 is the minimum, and no redirect is followed.
- **Toolbar.** The View group of the Commands toolbar gains the AI Assistant button after the
  three view buttons. A customised toolbar layout stored by 0.0.4 does not gain it by itself:
  add it in *Customize Toolbar* or press *Reset* there. The button is hidden under *Disabled*.
- **Hotkeys.** Ctrl+Shift+A (View > AI Assistant) and Ctrl+K (Ask AI...) are new default
  hotkeys - Cmd on macOS - and are rebindable in Settings > Hotkeys like every other; under
  *Disabled* they do nothing and the Hotkeys page does not list them.
- **Files in the user folders.** The data folder (the `user` folder of a portable copy) may
  gain `ai-services.json`, your copy of the service list created by *Edit list*, and the user
  scripts folder a `90_assistant` group - see the Scripts section. Nothing else new is stored;
  conversations are never written to disk.
- **Packages.** The core links libcurl and, on Linux and macOS, OpenSSL statically - no new
  runtime file, a larger core executable. The Linux packages add the Mozilla CA bundle and its
  notice (`certs/`); the Windows and macOS packages carry no bundle. The interface gains one
  lazily loaded bundle chunk (`ai-assistant-*.js`) that is requested only when the assistant is
  turned on for the first time in a session.
- **Interface.** Every new text - the settings page, the notice, the panel, the popup, the
  activity list, the banner, the proposal dialog, the menu and toolbar labels - exists in
  English, Russian and Ukrainian; a settings file with a language chosen changes nothing for
  you.
- **Core API** (for anyone driving `mfbe-core` directly): minor 4, additive - the `ai.*`
  family (`services`, `reloadServices`, `createUserServices`, `complete`, `models`, `test`),
  `app.openUrl`, `doc.fragmentToXml` / `doc.fragmentFromXml`, `schema.text`, `scripts.write`,
  the `ai` settings group, `session.aiPanelWidth`, the error codes 1200-1203 and four test
  hooks. Nothing of API minor 3 changes.

## Scripts

No bundled script's behaviour changes in this release and none is dropped: the `mfbe` scripting
interface, the script packages and the scripting guide are the ones of 0.0.4. What is new is
who can start a script and who can write one. The assistant runs a script of the effective
layers on request, nested in its own request - the script's dialogs appear as usual, its changes
are part of the request's one undo step, a script that needs a selection runs only on one, and
scripts run in the Body view only (in the Source view the assistant asks you to switch). A
script the assistant proposes is written only after you confirmed it in the proposal
dialog, into your user scripts folder under the group `90_assistant` (ids `assistant/<name>`;
the model may name another user group), with the whole package replaced when you let it change
a script written earlier; a bundled script is never modified. Scripts written this way are
ordinary user scripts: they run in the same sandbox, with the same `mfbe` allow-list, and can be
edited or deleted in the folder *Settings > Other > Open scripts folder* opens.

## Known limitations

- **Proxies come from the environment only.** The core honours `https_proxy` / `HTTPS_PROXY`,
  `http_proxy`, `all_proxy` / `ALL_PROXY` and `no_proxy` / `NO_PROXY`; there is no proxy field
  in Settings and no discovery of the system's proxy settings (Windows, macOS, GNOME or KDE).
  Addresses on this computer (`localhost`, `127.0.0.1`, `::1`) are always direct.
- **Corporate roots on Linux need the environment.** The Mozilla bundle the Linux packages ship
  is the last fallback, used only when the environment and the distribution provide no bundle;
  it knows nothing of an enterprise root. A company proxy that re-signs TLS traffic needs
  `SSL_CERT_FILE` (or `CURL_CA_BUNDLE`) pointing at a bundle that holds its root. Windows and
  macOS verify through the system store, enterprise roots included.
- **No redirect is followed.** A service that answers a 3xx is reported as such ("the address
  redirects - enter the final address"); following it would carry the key to wherever the
  service points.
- **The free services are free.** OVHcloud allows 2 requests per minute per model for anonymous
  use; Pollinations one request every 30 seconds per address. A limit is waited out for up to
  5 minutes per request; a longer wait ends the request. The bundled models and addresses were
  verified on the release day (table below); a service that changes its address or model is
  corrected in your copy of the list file without an update of the editor.
- **Kilo Gateway was dropped on release day: its free tier withdrew the verified model.** The
  replacement free model answered unstably at the release-day check, so the entry is not
  bundled; anyone who wants the service adds it to their copy of the list file.
- **LLM7.io was dropped on release day: its tool-call round trip answered 502 from the origin
  in two runs (proof-reading alone passed).** A service that cannot complete the tool-call
  exchange cannot operate the editor, so the entry is not bundled; anyone who wants the service
  adds it to their copy of the list file (its keyless use is undocumented and has a small daily
  token quota).
- **Pollinations serves answers from a cache shared by all its users.** A reply can be the text
  another client received for the same input - once observed as another client's budget error
  returned as an ordinary answer. The editor cannot tell such a reply from a real one: check the
  result and use Undo when it is not what you asked for.
- **Answers arrive whole.** Nothing streams: a slow service shows the elapsed time until its
  whole answer is there (OVHcloud's `gpt-oss-120b` spends most of its time reasoning). Cancel
  is the stop at any time; there is no cap on the number of exchanges a request may take.
- **No preview, no deletion guard.** A request's changes are applied to the book as one undo step
  and reported in the panel; a preview with accept/reject before the change, and a confirmation
  before a request that removes a large part of the book, were proposed and declined for this
  release - validation and Undo are the protection.
- **TLS on Windows and macOS is verified by hand.** The automated journeys run on all three
  systems against a loopback stand-in over plain `http`, and the core's TLS test uses OpenSSL,
  so Schannel (Windows) and SecTrust (macOS) are exercised by no automated test; the release-day
  section below records the manual check with the default service.
- **One model per free entry;** another model of the same service is a copy of the entry in
  your list file. Conversations are kept in memory for the open document only and are cleared
  when another document is opened, when the panel is closed or when the editor exits. The
  Description view has no *Ask AI...*: the description is changed through the panel.
- Still true from earlier releases: the macOS bundles are ad-hoc signed and need the one-time
  "Open Anyway" step; on Linux systems that restrict unprivileged user namespaces the AppImage
  runs without the Chromium sandbox (install the `.deb`/`.rpm` to keep it); Windows and macOS
  packages are built by CI only; the installer's own pages stay English; in a Wayland session
  the keyboard-layout switch on open is unavailable.
