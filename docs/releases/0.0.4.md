# Maxima Fiction Book Editor 0.0.4 - release notes

Draft of the GitHub release text for tag `v0.0.4` (2026-10-21). The release workflow
(`.github/workflows/release.yml`, step "Checksums and release notes") writes the headline, the
table of packages per platform, the SmartScreen note, the link to `docs/installing.md` and the
reference to `SHA256SUMS` itself when the tag is published; the sections below are the
hand-written part and do not repeat those. The complete list of changes is in `CHANGELOG.md`.

## The annotation is back where it was, the description travels, and the position is restored

Release 0.0.4 is the third batch of changes from the review of the editor, this time with a
tester's complaints. Two things the original FictionBook Editor had are back - the annotation
and the history as editable blocks at the top of the Body view and in the Document Tree, and a
divider that makes the Document Tree pane narrower or wider. The Description view learns the
Maxima Library's other person roles, a book's description can be imported from another FBD or
FB2 file and exported as an FBD file, a never-saved book gets a proposed file name that comes
out right on every computer, and the five complaints are fixed: titles are centred, the caret
and the selection travel between the Body and the Source view, spell checking leaves the
description alone, the keyboard layout can switch when a document is opened, and "Restore
position" restores the position. No bundled script changes its behaviour.

## What is new

1. **Annotation and history at the top of the Body view.** Two framed blocks captioned
   "Annotation" and "History" sit above the first body, as in the original, and the Document
   Tree lists them above the bodies. They are the same text as the Description view's
   annotation and history fields - edit it in either place. Find, Replace, the Words tool,
   spelling and Undo cover the blocks like the body text; a selection across a block boundary
   can be copied but not deleted; an element that is present but empty in the file is kept
   exactly as read until you edit it.
2. **A divider for the Document Tree pane.** Drag the boundary between the pane and the view -
   Body, Description or Source - to make the pane narrower or wider; both sides re-layout as
   you drag, the pane keeps at least 160 px and the view at least 320 px, and the width is
   remembered for the next start. View > Document Tree hides pane and divider together.
3. **Other persons in the Description view.** After Translators a new list takes the
   illustrators, editors, compilers, designers, commentators and the person a book is about -
   a role and three names each, Add and Remove - written exactly as the Maxima Library and the
   Maxima FBD Maker write them, so a book made here arrives in the library with its roles. A
   file's existing entries appear in the list and are written back unchanged while you do not
   edit them; the library's record-number entries stay plain Custom info rows. The Authors and
   Translators lists are as they were.
4. **File > Import > Description from FictionBook file...** takes the description of another
   `.fbd` or `.fb2` file into the open document. Into a freshly created, untouched document
   everything is imported at once; otherwise a dialog lists every entry found - with its value,
   the cover as a small picture - behind an unticked checkbox, and Import takes exactly what
   you tick. One Undo takes the whole import back; the book's text and images stay as they
   were.
5. **File > Export > Export as FBD...** writes the description as it is in the editor - cover
   and other referenced images included, one empty section in place of the text - as a
   stand-alone FBD file that passes FB2 2.1 validation, always UTF-8, validated first and
   never over the open document's own file.
6. **A proposed file name.** Save As for a book never saved proposes "Last name First name -
   Book title" in the book's own letters ("Толстой Лев - Война и мир.fb2"), "Untitled" in the
   interface language when there is neither; the name is cleaned of the characters file
   systems refuse and reaches the system's dialog as Unicode on Windows, Linux and macOS, so a
   Cyrillic name on a Windows with a German locale is spelt right. The encoding you choose in
   the dialog is the document's, as before.
7. **The caret and the selection travel between Body and Source.** Switching to the Source
   view puts the caret, or the selected range, on the same characters of the XML and scrolls
   them into view; switching back selects the same text in the Body view, also after you
   edited the XML. A place the Body view has no equivalent for lands at the start.
8. **"Restore position" restores the position** - on every way of leaving a book (New, Open,
   Recent Files, a file opened from the system, every save, Exit, the window's close button,
   the restart, the reload of a changed file) and every way of opening one, in the Body view,
   scrolled into view, without switching the active view; also after a visit to the Source
   view and after a restart, for the 100 files most recently remembered (`positions.json`, a
   record of its own beside Recent Files). A file that changed meanwhile opens at the paragraph
   now in that place.
9. **Spell checking leaves the description alone.** Only the editor's own checker marks
   words, and only in the Body view - the annotation and history blocks included; the browser
   engine's checker, which underlined English words in a Russian book's publisher or keywords
   with whatever dictionaries the system had, is off everywhere. The Spelling command and the
   highlighting toggle are available in every view as before.
10. **Titles are centred.** Body, section and poem titles and the titles inside epigraphs and
    cites are centred as the original showed them (subtitles already were); the lines of a
    stanza are left-aligned again. A stylesheet rule of the same weight had overridden both.
11. **Switch keyboard layout when a document is opened.** Settings > Other > Open File gains
    the option with the layout chosen from the system's list; every document opened - at
    start, File > New, Open, Recent Files, a double-click, a dropped file, the restart, the
    reload of a changed file - switches the editor's window to that layout. Only a layout the
    system already offers is ever activated; nothing is installed. Windows and X11 Linux; see
    the limitations below for Wayland and macOS.

## Upgrading from 0.0.3

- **Settings.** The settings file keeps every value. New keys take their defaults when they
  are absent: `session.treeWidth` (`260`, the fixed pane width of 0.0.3),
  `other.switchKeyboardLayout` (`false`), `other.keyboardLayoutId` and
  `other.keyboardLayoutName` (empty). Nothing switches the keyboard layout until you turn the
  option on.
- **Remembered positions.** They move from the Recent Files list to `positions.json`, next to
  `recent.json` in the configuration folder (the `user` folder of a portable copy). A position
  0.0.3 recorded for a book is converted the next time that book is opened, when it still fits
  the document; the Recent Files list itself and Clear Recent Files are unchanged.
- **Files.** An `<annotation>` or `<history>` element that is present but empty in a book is
  now written back as read; 0.0.3 dropped it on save. Role entries of the Maxima Library's
  format (`custom-info` with `info-type="mlillustrator"` and the other five types) are shown
  in the Other persons list and written back character for character while unedited; every
  other `custom-info` entry is the plain row it was.
- **Interface.** Every new text - the block captions, the Other persons list, the Import and
  Export entries and dialog, the Settings option and its Wayland note - exists in English,
  Russian and Ukrainian; a settings file with a language chosen changes nothing for you.
- **Core API** (for anyone driving `mfbe-core` directly): minor 3, additive. `doc.caret` is
  deprecated in favour of `doc.position` and is removed with the next major; `recent.json` no
  longer carries a `caret`.

## Scripts

No bundled script's behaviour changes in this release and none is dropped: the `mfbe`
scripting interface, the script packages and the scripting guide are the ones of 0.0.3. The
annotation and history blocks and the Other persons list are views of data the interface
already exposed - a script that changes the annotation through `mfbe.setDescription` sees its
change in the block, and a script reads the role entries as the `custom-info` rows they are.

## Known limitations

- **Wayland.** In a Wayland session the system offers an application no way to switch the
  keyboard layout, so the option is shown greyed out with the note "The system offers no way
  to switch the layout" - also when the editor's window is served through XWayland. The
  desktop's own input-source switch (GNOME, KDE, over D-Bus) is a candidate for a later
  release, not planned work.
- **macOS keyboard layout** is best effort: the editor selects the input source where the
  system allows it, and the system may keep its own choice (for example with "Automatically
  switch to a document's input source"). The macOS behaviour is verified by the CI job only.
- **Windows keyboard layout** is verified by the CI job's platform test, which switches a
  real layout for a test window, and by the requester's smoke test; a journey that drives the
  packaged editor's own window end to end is a candidate.
- **The file type in the Save dialog on Linux.** The GTK file chooser does not rename the
  extension of the proposed name when you switch the file type: keep "Last name First name -
  Book title.fb2" and pick "FictionBook descriptors (*.fbd)", and the file is saved as `.fb2`.
  Change the extension in the name box yourself.
- **The divider** is dragged with the mouse; resizing from the keyboard is a candidate.
- **The Source view's own caret** is kept within a session only; across sessions the
  remembered position is the Body view's.
- The epigraph's left margin and the title padding of the original's stylesheet were lost to
  the same cascade defect as the titles and are left as they were (candidates, not planned
  work); the import takes nothing from outside the file (the library's lookup service stays a
  candidate).
- Still true from earlier releases: the macOS bundles are ad-hoc signed and need the one-time
  "Open Anyway" step; on Linux systems that restrict unprivileged user namespaces the AppImage
  runs without the Chromium sandbox (install the `.deb`/`.rpm` to keep it); Windows and macOS
  packages are built by CI only; the installer's own pages stay English.
