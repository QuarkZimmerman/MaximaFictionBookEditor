# Maxima Fiction Book Editor 0.0.3 - release notes

Draft of the GitHub release text for tag `v0.0.3` (2026-10-17). The release workflow
(`.github/workflows/release.yml`, step "Checksums and release notes") writes the headline, the
table of packages per platform, the SmartScreen note, the link to `docs/installing.md` and the
reference to `SHA256SUMS` itself when the tag is published; the sections below are the
hand-written part and do not repeat those. The complete list of changes is in `CHANGELOG.md`.

## The editor speaks Ukrainian, shows a running script, and restarts when it says it will

Release 0.0.3 is the second batch of changes from the review of 0.0.2. The interface and the
built-in spell checking gain Ukrainian, a long script run is impossible to miss and can be
stopped, "Restart now?" really restarts the editor, spelling dictionaries for any language are
a folder copy away, the editor can check for a new version on a schedule you choose, dates are
written the way your system writes them, the Windows installer offers a desktop shortcut, and
the Source view completes tag names. No bundled script changes its behaviour.

## What is new

1. **Ukrainian interface and Ukrainian spelling.** Settings > View offers System default,
   English, Russian and Ukrainian; a first start on a Ukrainian system is in Ukrainian. Every
   menu, dialog, tooltip, message, genre name, language name and symbol name is translated -
   with the original FictionBook Editor's own Ukrainian wording wherever it had the text. Books
   in Ukrainian are spell-checked with the built-in `uk_UA` dictionary (the dict_uk
   dictionary): misspelt words marked, suggestions offered, apostrophes handled, in every
   package, nothing to download.
2. **A running script is unmistakable and can be stopped.** A banner above the document - in
   every view, whether or not the status bar is shown - names the script, counts the elapsed
   time, shows the progress it reports, moves a busy sign and offers Cancel. The book stays
   fully readable, nothing is greyed and the places the script highlights stay visible, but
   your edits are refused until the run ends, and no second script can start. Find, copy, the
   Help menu and Exit keep working. When the run ends the status bar says how long it took, and
   a run longer than five seconds also shows a short notice in the work area that goes away by
   itself.
3. **"Restart now?" restarts the editor.** After a language change, Yes asks to save as usual,
   closes the editor and starts it again by itself - the same copy (a portable one stays
   portable), the same book, the same window position and size, maximised if it was - in the
   new language. In 0.0.2 Yes only closed the editor.
4. **Spelling dictionaries from a folder.** Settings > View shows your dictionaries folder and
   opens it with one click; copy a Hunspell `.aff`/`.dic` pair into it (the dictionaries
   LibreOffice and Firefox use), press Apply, and books in that language are spell-checked. The
   list "Dictionaries in effect" shows every dictionary with its origin and every file the
   editor could not use with the reason. Built-in dictionaries are never replaced.
5. **Version check on a schedule.** Settings > Other > Version check: at every start, once a
   day, once a week, once a month (the default) or never. When the interval has passed, the
   editor makes the same single request as Help > Check for new version in the background and
   speaks up only when a newer version exists; the latest version and a failed check are
   silent. Nothing else is sent, nothing is downloaded.
6. **Dates the way your system writes them.** "Today" in the Description view and the document
   date the editor fills in for a new book write the date text in the long form of your
   system's regional settings - "17 октября 2026 г.", "17 жовтня 2026 р.", "October 17, 2026" -
   and the date value as `YYYY-MM-DD`; 0.0.2 wrote English month names. The text stays free
   text you can rewrite.
7. **Desktop shortcut.** The Windows installer offers "Create a shortcut on the desktop", ticked
   by default as in the original's installer; uninstalling removes it, an upgrade keeps your
   choice, and `INSTALLDESKTOPSHORTCUT=0` declines it in an unattended installation.
8. **Tag completion in the Source view.** Type `<` and the first letters of an element name to
   see the FB2 elements allowed at that place; type `</` to see only the elements open at the
   cursor and not yet closed, innermost first. Enter or Tab accepts, Esc dismisses, Ctrl+Space
   asks on demand; the switch is in Settings > View > XML source editor.

Also fixed: the editor opens where it was closed (0.0.2 remembered the window position and
size but never applied them), and closing the window by its title-bar button runs the same
"Save changes?" flow as File > Exit - in 0.0.2 unsaved changes were lost and a running script
was stopped without a word.

## Upgrading from 0.0.2

- **Settings.** The settings file keeps every value. New keys take their defaults when they
  are absent: `view.sourceTagCompletion` (`true`), `other.dictionariesFolder` (empty = the
  default folder), `other.versionCheck` (`monthly`) and `session.lastVersionCheck` (absent
  until a check gets an answer); `session.windowGeometry` may now carry the maximised state.
  With the default schedule and no recorded check, the first start after the upgrade makes the
  first version check; choose "never" in Settings > Other before that if you do not want it.
- **Installer.** The install-folder page has the new "Create a shortcut on the desktop"
  checkbox, ticked by default; 0.0.2 never created a shortcut, so an upgrade through the
  installer's pages creates one unless you untick the box. Unattended upgrades:
  `msiexec /i MaximaFictionBookEditor-0.0.3-win64.msi /qn INSTALLDESKTOPSHORTCUT=0` for no
  shortcut (the default `/qn` creates one). From 0.0.3 on the choice is recorded and kept at
  the next upgrade.
- **Licences.** The Ukrainian dictionary is run-time data the editor only reads; it ships
  under its own Mozilla Public License 1.1 notice (`resources/dictionaries/uk_UA.txt`), shown in
  Help > About with the other dictionaries' notices, and `THIRD-PARTY-NOTICES.md` lists such
  data files in their own "aggregated data" section. The editor itself stays GPL-3.0-only.
- **Portable copy.** Everything stays in the `bin\user` folder as in 0.0.2 - the dictionaries
  folder is `bin\user\dictionaries`, the recorded check time is in the settings file there -
  and a restart starts the same copy from the same place.
- **Interface.** A settings file with English or Russian chosen changes nothing for you. Under
  the Ukrainian interface the bundled scripts' own messages, prompts and forms show their
  English texts (the scripts carry Russian and English texts only); everything the editor
  adds to them is Ukrainian.

## Scripts

No bundled script's behaviour changes in this release and none is dropped: the `mfbe`
scripting interface, the script packages and the scripting guide's description of what a
script can do are the ones of 0.0.2. The quiet lock changes only what *you* may do while a
script runs - the script interface never let a script wait for the user to edit the text
directly, so nothing is taken away from any script. The scripting guide
(`docs/scripting/en.md`, `ru.md`, "While a script runs") lists what stays available during a
run.

## Known limitations

- The restart and the regional date text on Windows and macOS are verified by the CI jobs
  only (the Windows journey changes the language and restarts; the Windows and macOS legs run
  the date formatter's tests under their regional settings); the development host is Linux.
- The installer's new checkbox was verified by hand by the requester; CI verifies the
  unattended paths (default, `INSTALLDESKTOPSHORTCUT=0`, an in-place upgrade, uninstall) and
  that the shortcut starts the editor.
- The installer's own pages stay English, as they are for the Russian interface.
- Completion offers element names only - no attributes, attribute values or automatic closing
  tags; a floating symbol palette that stays open while you type is likewise a candidate for a
  later release. Both are recorded as candidate future features, not planned work.
- Still true from earlier releases: the macOS bundles are ad-hoc signed and need the one-time
  "Open Anyway" step; on Linux systems that restrict unprivileged user namespaces the AppImage
  runs without the Chromium sandbox (install the `.deb`/`.rpm` to keep it); Windows and macOS
  packages are built by CI only.
