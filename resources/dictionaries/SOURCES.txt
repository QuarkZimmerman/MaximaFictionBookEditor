Hunspell reads the .dic file in the encoding declared by the .aff "SET" line,
so the files must stay byte-exact; do not re-encode or normalise them.

Versions
--------
  en_US : SCOWL-derived "en_US Hunspell Dictionary" version 2020.12.07
          (http://wordlist.sourceforge.net, see en_US.txt); the .aff carries
          LibreOffice fixes up to 2024-01-29 (Marco A.G. Pinto).
  ru_RU : Russian dictionary (BSD-style licence, see ru_RU.txt),
          with the 2012-08-24 TRY-line fix by Laszlo Nemeth (see ru_RU.txt).

Regeneration
------------
  SHA=67032ee957631908098a72edf48dc81cac27e369
  BASE=https://raw.githubusercontent.com/LibreOffice/dictionaries/$SHA
  curl -fL -o en_US.aff $BASE/en/en_US.aff
  curl -fL -o en_US.dic $BASE/en/en_US.dic
  curl -fL -o en_US.txt $BASE/en/README_en_US.txt
  curl -fL -o ru_RU.aff $BASE/ru_RU/ru_RU.aff
  curl -fL -o ru_RU.dic $BASE/ru_RU/ru_RU.dic
  curl -fL -o ru_RU.txt $BASE/ru_RU/README_ru_RU.txt
  sha256sum -c   # against the table above
To update to a newer upstream state, take the new SHA from
https://api.github.com/repos/LibreOffice/dictionaries/commits/master and
refresh the table above.
